02　原本はローカル、利用者データはオンライン

公開情報の流れ

公開後はPCを止めても、配信済みサイトを閲覧できます。

更新時だけローカル原本を編集し、検査して同じデータ版から再生成・配布します。公開サイトから自宅PCのDBへ接続しません。公開ページに反映されるのは次回配布後です。

利用者データの流れ

ブラウザでログイン

お気に入り・メモ・家族共有・中心地点などを保存。

Supabaseで利用者別に保管

認証とRLSを維持。学校IDで静的データと結び付けます。

学校や土地の原本をクラウドDBへ重複保存しない設計です。同じSupabaseを使っても別サブドメインのログイン状態は自動共有されないため、再ログイン・ゲスト連携を確認します。

移行時は「学校テーブルを削除するだけ」にしない

現行の学校IDは、お気に入り・メモ・利用者の偏差値記録から外部キーで参照され、学校行の削除に連動して保存内容を削除する設定があります。学校IDを保ち、参照の付替えとデータ保持を先に検証してから原本を移します。最小ID参照表を一時的に残す案も比較し、その容量は共通枠へ含めます。

管理者の修正・審査は現在DBの学校情報を読むため、ローカル原本へ反映して再生成する経路へ改めます。利用者の変更提案を受ける場合も、原本へ自動混入させず採用処理を分けます。保守設定や計測イベントなど既存の小さなオンライン依存は、配置と保存期間を個別に整理します。

ローカルDBと公開作業の選び方

原本はSQLiteをサービス単位で使う方針を採用しました。MariaDB等の導入は現時点で不要とし、将来の同時更新で支障が出た場合に再評価します。現行PostgreSQLとのSQL・型・拡張機能の差は移植時に確認します。

原本のスナップショット → 公開許可項目だけ抽出 → 件数・ID・容量を検査 → HTML/JSON生成 → 配布、の順にします。原本DBファイルをそのまま公開せず、個人データを静的生成物へ混ぜません。バックアップからの復元と、前の公開版へ戻す手順も用意します。

生成済み成果物はWrangler経由のDirect Uploadを比較案の中心に置きます。既存Git連携プロジェクトの自動公開と競合しない切替が必要です。管理画面のドラッグ＆ドロップは1,000ファイル上限・Functionsの制約があるため、この規模の配布方式にはしません。

SQLiteの適した用途／Cloudflare Direct Upload。本資料は設計更新であり、DB移設・原本削除・自動公開設定の変更は行っていません。

合意した運用方針：編集する原本は1つ、控えを複数へ

ローカル原本から静的生成し、利用者保存をオンラインへ分離する方針は了承済み。SQLiteを採用し、実際の保存先と保持世代は実装計画で具体化します。

原本：ローカル1か所

普段の編集・取込み先を固定。複数のコピーをそれぞれ編集する運用にはしません。

整合したバックアップを作る

SQLiteのBackup API等で完成したコピーを作り、検査して日付・データ版を付けます。

別ドライブ＋Google Drive

完成したコピーを複製。同期先を編集用の原本にせず、旧世代も残します。

保存先の候補: C・D・EドライブとGoogle Drive。ドライブ文字が違っても同じ物理ディスクなら故障への備えは一つなので、配置時に実体と空き容量を確認します。Google Drive側の空き容量も別に確認します。

SQLiteの手順: 書込み中のDB本体だけをコピーせず、Backup APIまたはVACUUM INTO等で一貫したコピーを生成 → 完了後に整合性・件数・データ版を確認 → 日付付きバックアップを別媒体と同期先へ配布 → 同期完了と復元を確認。WALに未反映の内容が残る場合も考慮します。

同期は誤削除も伝わり得るため、世代を残すバックアップとして設計します。保持世代数・頻度は実容量に合わせて決定。上の容量バーの「原本＋バックアップ等の本数」は試算値で、PC側の同期コピーを含む各保存先の実容量も別途数えます。MariaDB等を選ぶ場合は、そのDBに適したバックアップ方式を用います。

SQLite Backup API／WALの扱い。保存先の設定・DB導入・バックアップ実行はまだ行っていません。

$5 が必要になるのは、どんなときか

Free の処理回数や CPU の枠では必要な動作を維持できないときに、Workers Paid を比較します。静的配信だけならリクエストは無料・無制限ですが、現行の学校 HTML はメンテナンス等の middleware を通る構成なので、全アクセスを静的無料とは数えられません。

料金を下げるために処理を外す場合も、メンテナンス表示、直接 URL からの表示、検索除外などの機能を保って検証します。Paid は account 月 $5 から、月 1,000 万回＋3,000 万 CPU ms が基本枠です。

Workers 料金と超過単価／Functions の呼出し経路。現契約と実利用量は未確認です。
