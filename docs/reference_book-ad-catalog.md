# 過去問PRの外部JSON配信

学校詳細の過去問PRは、実行時にGitHub上の公開JSONから読み込む。商品情報をJavaScriptバンドルやプリレンダーHTMLへ埋め込まない。初期表示はPRなしで、取得後に表示する。対象は公立高校（県立・市立・組合立）。開校予定・閉校予定・閉校・高校募集なし・募集終了は除外する。

## 初回の構成

この公開リポジトリの広告専用ブランチ `book-ads` に、`book-ads/01.json`〜`book-ads/47.json`を配置する。アプリはGitHub Rawから直接読む。R2、Pages Functions、配信用の認証情報は不要。公開するのは表示用JSONのみで、選定記録・管理画面の情報・秘密値を含めない。

読込先は [book-ads-source.json](../web/data/book-ads-source.json) の `baseUrl` で指定する。現在の設定では群馬のURLは `https://raw.githubusercontent.com/ishizakahiroshi/manabi-map/book-ads/book-ads/10.json`。前の`book-ads`がブランチ名、後ろがディレクトリ名。追従するブランチを使い、固定コミットSHAは使わない。

初回は次の順に進める。

1. Cloudflare PagesのPreviewビルド対象から`book-ads`ブランチを除外する。GitHub Actions側の対象ブランチも確認する。広告更新でアプリのビルドを起動させないための設定で、実環境の確認は別途必要。
2. 生成した`book-ads/`ディレクトリをデータ専用ブランチへ配置・公開し、47県のRaw URLがHTTP 200で読めることを確認する。アプリの履歴やソースを載せない専用ブランチとし、main/developへマージしない。
3. 読込機能を初回デプロイし、実際の学校詳細を確認する。JSON未公開のまま先にアプリを出すと、群馬を含むPRが非表示になる。

以後、同じデータ形式のPR追加・差替え・停止はデータブランチのJSON更新だけで行える。読込先URLやデータ形式を変える場合にはアプリ側の変更・デプロイが必要。ブランドやドメインは商品データに含めない。

## 編集と投入

編集元は [合成データの入力例](../examples/book-ads.json) と同じJSON。実際の商品・受験年度・正規の紹介リンクを担当者が確認して入力する。入力例は無効であり、実商品や実紹介IDを含まない。`examYear`は確認用で、年度だけで自動終了しない。終了日時は`endsAt`を設定する。

| 項目 | 意味 |
|---|---|
| version | 1固定 |
| enabled | カタログ全体の掲載許可。falseで全停止 |
| ads | 掲載順の配列。各学校には一致する先頭の有効広告1件 |
| id | 英小文字・数字・ハイフンの一意ID。クリック計測にも使う |
| prefectureCode | 01〜47の文字列。全国共通商品の暗黙代用はしない |
| title / publisher / examYear | 書名・出版社・受験年度 |
| enabled（各広告） | その広告の掲載許可 |
| startsAt / endsAt | 任意。UTCのISO日時（例`2027-04-01T00:00:00.000Z`）。開始を含み終了を含まない |
| links | Amazon、楽天の順に2件。提供元発行のhttps URLをそのまま入れる |
| coverHtml | 任意。楽天発行の128px画像のみのa/img HTML。未対応形式は掲載せず担当者が確認 |

リポジトリルートから実行する。引数の入力・出力は担当者が管理する外部ファイルの場所を指定する。

```text
node scripts/prepare-book-ads.ts <編集元.json>
node scripts/prepare-book-ads.ts <編集元.json> <出力ディレクトリ>
```

前者は検証のみ。後者は`<出力ディレクトリ>/book-ads/01.json`〜`47.json`を生成する。アップロード・アプリビルド・デプロイはしない。生成前に全件を検証し、各県64KiB以下に制限する。元JSONの余分な管理項目は配信物へ含めない。

生成したファイルをデータブランチの同じパス（`book-ads/10.json`など）へアップロードする。GitHubのファイル編集・アップロード画面でも更新できる。通常は変更県だけでよい。全停止や削除を反映するときは空県のファイルも含めて更新する。編集元も保管し、Gitの履歴で差分と以前の版を確認できる状態にする。Gitへの記録が一括でも、Raw配信のキャッシュは県ごとに更新され、全県同時反映は保証しない。

## 反映と停止

学校詳細を開いた時、表示中の5分間隔、タブへ戻った時に新たに取得する。ブラウザへの要求は`cache: no-store`、認証情報は送信しない。ただしGitHub側の共有キャッシュを無効にするものではない。2026-09-27の実応答では`Cache-Control: max-age=300`だった。ページ再読み込みでも即時反映は保証しないため、通常の反映に数分の遅れを許容する運用とする。緊急の即時停止を保証する仕組みではない。

RawはJSONでも`text/plain`を返すため、`application/json`と`text/plain`を受理した上でJSONの内容・サイズ・schemaを検証する。5秒で取得を打ち切り、失敗・不正データ・対象なしならPRのみ非表示にする。前回の広告をstorageへ保存して復活させない。

停止は対象広告の`enabled:false`、県全体の`enabled:false`、またはその県の`ads:[]`を生成・差替えする。ロールバックはGit履歴の県ファイルを同じパスへ戻す。学校本文は広告の成否に依存しない。未登録県にサンプル広告は表示しない。

URLにUTMを足さない。楽天の提供HTMLは許可した単一a/img構造・属性・通信先だけを検証し、受理した原文は変更しない。script、イベント属性、任意CSS、別ホスト等は拒否する。画像は従来の128版1枚に制限し、外部画像を追加する場合は通信量を実測してから掲載する。[楽天のガイドライン](https://affiliate.rakuten.co.jp/guideline/rule/)

## 検証と公開条件

関連テストは`web`で`pnpm exec vitest run src/lib/bookAdCatalog.test.ts src/lib/bookAdSource.test.ts src/components/BookAdSlot.test.ts`。合成データで47県の選別、対象外学校、危険URL/HTML、期間、取得失敗、RawのMIME形式、配信サイズ上限を確認する。

ローカル検証では公開情報の`VITE_BOOK_ADS_BASE_URL`を指定すると読込先を上書きできる。これは起動/ビルド時の設定であり、広告内容の更新とは異なる。本番のCSP設定ファイルには`raw.githubusercontent.com`を追加済み。他の配信元に変える場合はCORSとCSPも確認する。

本番公開前には県別Raw応答、学校詳細での県一致・表紙・広告表記、取得失敗・差替え・停止・再表示を確認する。ローカル検証は本番配信や購入報酬の確認を代替しない。
