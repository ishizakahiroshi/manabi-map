# Manabi Map の製品・運用ルール

`CLAUDE.md` から降格した、公開リポジトリで共有する製品境界・表示・データ・リリース規約の正本。機械で強制できるルールは、本文ではなく参照先のコードやテストを更新する。

## 製品の境界

- Web（PWA）を正本とする。高校版の Android 対応と iPhone 向けの提供方針は、下記の[提供プラットフォームと採算の判断](#platform-policy)に従う。exe 化は行わない。
- 学校選びの補助を目的とし、巨大な偏差値サイト・ランキングサイト・合否煽りにはしない。
- 商用偏差値サイトのスクレイピング・数値転載、自由口コミの大量収集、有料課金の本実装は行わない。
- 学校・教育委員会・報道機関への対外的な持ち込みや告知は現在保留。自然流入と受け身の問い合わせ対応は続ける。

## 提供プラットフォームと採算の判断

2026-09-27 の方針決定。高校版は、当面 Web 版と Android 版に注力する。iPhone 利用者には Web 版を案内する。

- **Web 版**: 画面・機能の共通基盤として継続提供する。iPhone からの利用も提供対象とする。
- **Android 版**: 既存の Web 版とバックエンドを活かし、承認済みの試作から公開に向けて進める。この方針決定をストア公開済み・審査済みとは扱わない。
- **iPhone 専用アプリ**: 現時点では着手しない。開発者登録の継続費用と、iOS 固有の開発・認証・審査・保守の負担を、広告収入等でまかなえる見通しが立った段階で再検討する。
- **判断の理由**: 収益が見通せない段階では固定費と保守対象を増やさず、Web と Android の利用・収益の実績を確かめる。iPhone 利用者への提供は Web 版で続ける。
- **再検討の基準**: 継続的な収益実績と、その時点の費用・開発保守負担を比較し、採算が見合うかを判断する。具体的な収益額・期間・着手日は未設定。利用者増だけを iPhone 専用版の着手条件にしない。
- **記録の扱い**: 本節は継続的な提供方針であり、期限付きの pending や自動着手する作業項目にはしない。再検討時にユーザーが方針を決め、着手を決めた場合に実装計画を作る。
- **実装の境界**: Android 試作の存在を、Capacitor 等の導入、iOS プロジェクトの追加、他サービスのアプリ化への包括的な承認とは扱わない。共通の Web 資産とバックエンドを活かせる構成を保つ。

## ブランドと URL

**ブランドの差替え可能性は必須要件。** 本節を、総合入口と関連サービスの開発リポジトリに共通する公開仕様の正本とする。個別の計画・デザイン資料は本節を参照し、異なるルールを別々に管理しない。各リポジトリのAI向け入口から本節へ辿れるようにする。

- サービスの URL は機能・分野の名前のサブドメイン（`<機能名>.manabi-map.app`）を基本とし、表示ブランドと接続先を別設定で管理する。改名だけではURLを変えない。独自ドメインへの昇格や権利関係等でドメイン変更が必要になった場合は、認証・保存・SEO・ページ単位の転送を含む別の移行として扱う。
- 既存の学校検索は `manabi-map.app` の直下で公開している。移すときは旧 URL を対応するページへ 1 本ずつ 301 し、トップへまとめて飛ばさない。
- DB のテーブル名・列名、API のパス、Cloudflare Pages のプロジェクト名、ディレクトリ名には、サービス名ではなく機能の名前を使う。
- サービスごとの機能識別子をキーに、表示名・短縮名・言語別表記・ロゴ・共有画像をブランド設定へ集約する。画面、title、OGP、JSON-LD、PWA manifest、静的生成ページは同じ設定を参照し、コンポーネントや生成スクリプトへ直書きしない。総合入口のサービスカードにも同じ表示を反映する。ブランドの共通化やリポジトリの統合は要求しない。
- 表示名をDB・API・データID・保存キーと切り離す。改名のためだけのDB移行や利用者データの初期化を必要としない構成にする。既存識別子に旧名が残っていても、表示だけを変える作業で機械的に改名しない。
- 既存の直書きは、改名の発生を待たず次の入口整備・移行・該当機能の改修計画へ集約作業を組み込む。新規実装は初めから本要件を満たす。規約、README、配布資料、画像内の文字、外部掲載など設定だけで更新できない対象は差替え一覧として管理する。
- リリース前の検収では、合成の別ブランド設定で画面・SEO・PWA・生成物の表記を確認し、URL・既存ID・保存データが維持されることを確かめる。資産・キャッシュ更新と元のブランドへ戻す手順を用意する。文書に要件を書いたことを、実装・検証済みとは扱わない。
- 新しいサービス名は、商標の一次調査を済ませてから公開ファイル（コード・文書・コミットメッセージ）へ入れる。個別の名前と移行の計画は作者環境の `docs/local/reference_brand-and-naming.md` を読む。

### 実装計画と変更対象の管理

学校・学校入口・総合入口の表示設定は `web/data/brands.json` の `high-school` / `school` / `apex` で管理する。接続先は既存 `site.json` / `deployment-targets.json` に残し、表示名の変更で認証・API・ID・保存キーを変更しない。Node側は `web/scripts/lib/brands.mjs`、ブラウザ側は `web/src/lib/brand.ts` から同じ設定を読み、生成HTML・SEO・PWAにも反映する。

合成検収には `build-school-candidates.mjs` の `--brands=<合成設定JSON>` を使う。合成snapshotとmanifest、新規のリポ外出力を明示し、通常の本番取得付きbuildへ代替しない。検収用設定は隔離コピーだけに適用するため、元設定の復元は不要。実際の改名時は旧設定/資産を保存し、候補の画面・title・OGP・JSON-LD・manifestと相互リンクを照合した後、別途許可された公開へ進む。復旧時は旧設定/資産の完成世代へ戻し、同じ検査を行う。規約・配布PDF・画像内文字・外部認証やSNSの表示は手動対象として確認する。

各リポジトリは、既存実装のブランド設定集約を作業キューの計画へ紐付け、担当・対象ファイル・再確認期日・検収条件を記録する。公開済みの旧計画を未着手へ戻す代わりに、後続の変更として追跡する。共通ルールの更新時は、それを参照する設計書と現役計画の矛盾も直す。

ブランド変更一覧には、自サイトの画面・生成物に加え、利用中のOAuth同意画面、認証メールの件名・本文・送信者表示、SNSプロフィール、外部掲載、配布PDF・QRを含める。サービスごとに管理場所・変更担当・現在の表記・変更後の表記・検証結果を持ち、未確認と対象外を区別する。認証の表示名を変えるためにclient ID・秘密鍵・callback URLを機械的に変更しない。メール・外部プロフィール等は変更計画への記載だけで送信・更新したと扱わない。

サービス間のカード・戻りリンクは、提供側と掲載側のリポジトリを対応付けて更新し、公開前後に両方の表示名とリンク先を確認する。設定・画像・生成物の世代、手動差替え対象の残件も切替記録へ残す。

### 商標の定点観測と切替方針

運用責任者・確認した担当者・確認日・結果・出典・次の対応を運用記録へ残す。次回の実行日は作業キューの `due` を正本とし、確認後に担当者が更新する。取得不能は「未確認」と記録し、最後に確認できた結果と分ける。未確認のまま最終確認日を更新したり、次回日を通常の1か月先へ送ったりしない。確認できなかった対象と再確認予定を残す。

当面は現名称を使い、関連する商標案件を原則月1回確認する。一覧表示だけで判断せず、詳細・経過情報の登録査定、登録番号・登録日、拒絶査定、審判を確認し、確認日と出典を記録する。登録査定を把握した時点で切替準備を見直し、商標の設定登録を確認した時点で対象ブランドの変更へ進める。侵害の主張が届くまで待つことを前提にしない。各サービスは独立して変更できるようにし、関係しないブランドの一括改名は要求しない。

観測対象・確認予定日・調査履歴は作者環境の運用記録で管理し、本節へ案件の詳細を転載しない。候補選定、差替え範囲、ドメインの扱い、公開手順を具体化して切り替える。定点観測の記録を自動監視の稼働と混同せず、未決定の名前への自動改名・自動公開は行わない。

## 通信量（ギガ）

- **主な利用者は中高生で、モバイル回線の残量が少ない前提で作る。**画面の見栄えのために通信量を使わない。
- 見た目のための Web フォント・大きな画像・装飾用の外部リソースは持ち込まない。日本語 Web フォントは特に重く、2026-09-11 に県ページ 1 枚で実測 約 2.8MB（本体の 9 倍）だったため全廃した。
- 初期表示に要らないデータは、そのとき必要な分だけ取る。全国分の一括取得を既定にしない。
- 外部ドメインからの取得を足すときは、**足す前に転送量を実測する**。「軽いはず」で入れない。
- 実測と削減の進行は `docs/local/plan_data-usage-audit.md` を参照する。

## 広告

- 手動選定した塾・予備校・学校・通信教育など、進路・教育に直接関係する広告だけを控えめに表示する。
- ランダム配信の無差別アドネットワーク、金融・ギャンブル・アダルト・情報商材、モーダル / 自動再生 / 追従バナーは使わない。
- 広告は「広告（PR）」と明示し、NPO / 自治体連携版では全 OFF とする。実装は `web/src/components/AdSlot.tsx` を入口にする。

## SSR・hydration

- プリレンダーは `web/src/entry-server.tsx` と `web/scripts/gen-seo-pages.mjs` の React 実出力を使う。別 HTML を手書きして同じ画面を再現しない。
- `useState` の初期値で `localStorage` / `sessionStorage` を読まない。初回 render は既定値、復元は `useEffect` で行う。
- fetch 結果で初期表示が変わるページは `web/src/lib/initialData.ts` の `#__MM_INITIAL__` に埋め込み、`#root` の外に置く。
- 静的出力は `web/scripts/verify-static-output.mjs` と `web/scripts/verify-static-output.test.mjs` で検査する。文字列の完全一致ではなく、必要なタグと内容の包含を検査する。

## ナビゲーション

- 導線を変えるときは `web/src/components/Sidebar.tsx` と `web/src/components/SiteFooter.tsx` の両面を確認する。地図画面にはフッターが無い。
- フッターの表示ラベルは `web/data/site-footer-links.json`、公開方針の文言は `web/data/dataset-claims.json` を正本とし、コンポーネントへ直書きしない。
- 静的出力テストで再ハードコードを検出する。

## データ・公開 API・個人情報

- 検索地点は「自宅住所」ではなく中心地点として扱い、お気に入り・メモ・個人推計は RLS で本人限定にする。
- 偏差値相当値は公的資料を参考にした編集推計で、根拠が確認できないものは掲載しない。商用サイト由来の値を混ぜない。
- 静的 HTML には画面表示として含められるが、公開 API には偏差値相当値を出さない。`findDeviationLeak()` が `/api/v1/` の JSON を検査する。
- データセットの定義・出典・ライセンスは `DATA.md`、DB の構造・RLS は `web/supabase/migrations/` と `web/supabase/baseline_schema.sql` を正本とする。

## リリース・外部サービス

- `main` は本番、`develop` は Preview。main へ直接コミットせず、release plan の検証とユーザーの明示承認を経てマージする。
- Cloudflare Pages は main push で本番反映される。タグは versioned release の記録用アンカーであり、デプロイの代替ではない。
- Supabase の schema / RLS / function 変更は `web/supabase/migrations/` に置く。学校データの大量投入は公開 repo に出す意思がある場合だけ migration 化し、適用は人間が内容確認してから行う。
- 外部サービスの設定はリポジトリ検索で推測しない。作者環境の `docs/local/reference_external-services.md` を Read し、変更と同じターンで台帳も更新する。
- `scripts/maintenance.mjs` の on / off / status は service role key を読むため、秘密を出力・ログ・コミットしない。

## 秘密情報と公開 fixture

- 公開 fixture・サンプル設定・例示プロンプトは最初から合成データで書く。実データや外部 KB の表示名を公開ファイルへ残さない。
- layer 1 は `node scripts/secrets-scan.mjs --staged --block`、layer 2 は `.githooks/pre-commit`、layer 3 は `.github/workflows/secrets-scan.yml`。
- 秘密値は repo 外の環境へ置き、公開ファイルにはパスや鍵の値を写さない。
